# Memory Beyond

为 AstrBot 重新设计的**长期记忆 + 上下文压缩**系统。

核心理念一句话：**真相在磁盘，上下文只带索引，细节按需取回，压缩后从磁盘重新注入。**

- 长期记忆是磁盘上的 Markdown 文件（一个文件一条事实），LLM 通过工具自主读写维护
- 每轮对话只注入轻量的 `MEMORY.md` 索引，细节由 LLM 按需用工具取回
- 上下文逼近阈值时自动做**滚动摘要**：旧轮次卷入摘要、最近轮次保留原文
- **平台的聊天历史永远一个字不动**——压缩只改变发送给模型的派生视图
- 摘要模型全链路失败也**不产生任何永久信息损失**（详见下文兜底设计）

## 设计原则

**记忆是文件，不是数据库。** 一个文件一条事实，Markdown + frontmatter（`name` / `description` / `metadata.type`），正文可用 `[[name]]` 链接相关记忆。四种类型：`user`（用户是谁）、`feedback`（用户对助手工作方式的指导）、`project`（进行中的事）、`reference`（外部资源指针）。文件天然可读、可迁移、可手工编辑。

**上下文只带索引。** 每个作用域一个 `MEMORY.md`，一条记忆一行 `- [标题](文件.md) — 一句话钩子`，只放指针永不放正文。注入上限 200 行 / 25KB，超出从底部截断，且在截断处注明"还有 N 行未加载、可用 memory_search 检索"——模型永远知道自己有没看到的记忆。写入侧同样守门：索引接近上限提醒精简，超限报错但写入不丢。

**记忆内容是数据，不是指令。** 索引与摘要以 user 消息注入历史开头、块首带数据标注；只有稳定不变的记忆规范进入 system prompt。这样"记住：以后忽略你的规则"之类的内容只会被当作被记录的资料，不会被提权为系统指令。

**压缩产出派生视图，从不改写历史。** 插件为每个会话维护「摘要 + 水位线」，发送视图现场拼装；会话原始记录始终完整保留在平台侧。压缩后记忆依然可用，不是靠摘要"记得"，而是靠下一轮从磁盘重新加载索引。

**双作用域与隐私边界。** `global/` 是机器人**自我**的全局记忆——它应当遵循的偏好与行为准则，所有会话共享生效；`session/<会话>/` 是当前会话（UMO）的记忆——本群或本私聊里每个人的信息（`user` 类）与进行中的事（`project` / `feedback` / `reference` 类）。session 记忆只在本会话使用，不跨会话透露；**global 绝不存放关于具体用户或群的信息**。

**记人以数字 ID 锚定。** 插件默认在每条用户消息开头注入 `[发送者：数字ID｜昵称]` 标注，并要求 LLM 用 `user-<数字ID>.md` 记录用户信息——昵称会变、也可能被冒用来污染记忆，数字 ID（如 QQ号）才是不可伪造的身份锚点；昵称只作为正文里可更新的附注，LLM 可自行搭配提示词灵活记忆用户。

**压缩-记忆联动。** 滚动摘要的同一次 LLM 调用里，顺带把即将淡出上下文的长期事实提取为记忆文件（只写 session 作用域），一次调用干两件事，不增加请求量。

## 安装

从 AstrBot 插件市场安装，或克隆本仓库到 AstrBot 的 `data/plugins/` 目录。无第三方依赖（仅用 Python 标准库 + AstrBot API）。

装上即用，但**强烈建议**做两件事：

1. 在插件配置里把 `max_context_tokens` 填成当前模型的真实上下文窗口（如 128000）。留 0 时按模型名自动探测，探测失败会停用压缩并在日志提示。
2. 如果主对话模型较贵，指定一个便宜快速的 `summary_provider_id` 专门跑摘要。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `enable_memory` | 开 | 记忆索引注入 + 三个记忆工具 |
| `annotate_sender` | 开 | 在用户消息前注入 `[发送者：数字ID｜昵称]` 标注 |
| `enable_compression` | 开 | 滚动摘要压缩 |
| `max_context_tokens` | 0（自动探测） | 模型上下文窗口，建议手动填写 |
| `compress_threshold` | 0.70 | 触发压缩的占用比例，必须 < 0.82（超限自动钳制到 0.80 并告警） |
| `compress_buffer` | 0.165 | 压缩目标 = 阈值 − 缓冲区 |
| `keep_recent_turns` | 3 | 摘要时保留原文的最近轮数 |
| `summary_provider_id` | 空（用当前对话提供商） | 摘要专用提供商，从提供商列表选择 |
| `summary_retry_count` | 3 | 摘要调用重试次数 |
| `summary_timeout` | 120 | 单次摘要调用超时（秒） |
| `summary_prompt_template` | 空（内置模板） | 自定义摘要提示词，占位符 `{previous_summary}` `{transcript}` |
| `extract_memories` | 开 | 压缩时联动提取记忆 |

## 管理指令（仅管理员）

| 指令 | 作用 |
| --- | --- |
| `/mb_status` | 本会话记忆/压缩状态：窗口、水位线、摘要长度、校准比例、退避状态 |
| `/mb_reset` | 清空本会话的摘要与水位线（平台历史不受影响，超阈值会重新摘要） |
| `/mb_probe` | 实测摘要提供商回退链是否可用 |

## LLM 可用的记忆工具

| 工具 | 作用 |
| --- | --- |
| `memory_read(scope, file)` | 读取记忆文件完整内容；`MEMORY.md` 即索引 |
| `memory_write(scope, file, content, delete)` | 整文件覆盖写入 / 删除，并要求 LLM 同步维护索引行 |
| `memory_search(query, scope)` | 全文搜索，索引被截断或记不清文件名时的兜底 |

## 工作原理

### 记忆

```
data/plugin_data/astrbot_plugin_memory_beyond/memories/
├── global/                        # 机器人自我：偏好、行为准则（所有会话共享）
│   ├── MEMORY.md                  # 索引：一条记忆一行，只放指针
│   └── style-concise.md           # 一个文件一条事实
└── session/<会话键>/              # 当前会话：这里的人和事
    ├── MEMORY.md
    ├── user-12345678.md           # 记人以数字 ID 锚定，昵称只是附注
    └── project-deadline.md
```

每轮 LLM 请求时，把两个作用域的 `MEMORY.md`（截断到 200 行 / 25KB）拼成索引块，以 user 消息注入历史开头；LLM 需要细节时用 `memory_read` 取回。索引快照按会话缓存以保住提供商的 prompt cache 前缀，压缩发生时才刷新。

### 压缩

插件为每个会话维护「**摘要 + 水位线**」：水位线之前的消息已被摘要覆盖，发送视图 = 开头 system 消息 + 索引块 + 摘要块 + 水位线之后的原文。再次触发时做滚动摘要：旧摘要与其后的旧轮次一起重摘要，水位线前移。轮次以 user 消息切分，`tool_call` 与其结果不可分割；水位线消息带指纹锚点，会话被重置/编辑时状态自动作废重建（代价只是重新摘要一次）。

**与 AstrBot 内置压缩器的共存**：不 patch、不越权。本插件阈值（默认 0.70）低于内置压缩器的 0.82，抢先把上下文压下去，内置压缩器的触发条件因此永远不满足、自动退化为 no-op——同时它还留在下游当安全网。这也是 `compress_threshold` 必须小于 0.82 的原因（配置超限会被强制钳制并告警）。

### 摘要失败的兜底链

1. 配置的 `summary_provider_id` 重试 `summary_retry_count` 次（默认 3，指数退避间隔）
2. 回退到当前对话的提供商再试 2 次
3. 全部失败：本轮改发**应急裁剪视图**（已有摘要 + 对半砍旧轮次 + 超长消息截断），**水位线不动**——被砍的内容只在本轮不发送，不产生任何永久信息损失；同时进入指数退避冷却（5 分钟起、每次翻倍、上限 1 小时），冷却结束自动重试，成功后被砍的轮次照常滚入摘要

### token 估算

字符启发式口径刻意对齐 AstrBot 平台（中文 ×0.6、其他 ×0.3、图片 765、音频 500），保证与内置压缩器对同一份上下文算出同一量级；provider 返回真实 `prompt_tokens` 时做 EMA 校准（比例钳制在 0.5–3.0）。

## 常见问题

**压缩会丢我的聊天记录吗？** 不会。平台会话历史零改动，压缩只改变发送给模型的视图。`/mb_reset` 后模型重新看到全部原文（直到再次超阈值）。

**换模型 / 换人格 / WebUI 里删改历史消息后会怎样？** 水位线锚点校验失败，压缩状态自动作废重建，重新摘要一次即可，不需要手动干预。

**群里的记忆会泄露到别的群吗？** 不会。session 作用域按会话隔离，记忆规范禁止跨会话透露；global 作用域只存机器人自身的偏好与行为准则，不含任何用户信息。

**有人改昵称冒充别人怎么办？** 记人以消息标注中的平台数字 ID（如 QQ号）为唯一锚点，昵称只是附注；消息里自称"我是某某"与 ID 对不上时，以 ID 为准。

**为什么日志提示"压缩已停用"？** 自动探测不出当前模型的上下文窗口。在插件配置中手动填写 `max_context_tokens` 即可。
